Plany Audit v6.0.1

A code-level audit of plany.work covering security, data loss, logic, printing, native builds, UI, accessibility, performance and features. Each finding cites the file and line it was found at.

September 23, 2026 · Scope: app.js (19,472 lines), index.html, styles.css, sw.js, functions/index.js, Firestore and Storage rules, manifest, Capacitor config. The login page and a locally served build were also rendered with Playwright and checked with axe-core. The critical findings were confirmed by re-reading the source. Nothing was changed.

Start here

The five that matter most

  1. Anyone with a Plany account can sign in as a teacher who used "Sign in with Microsoft". The Firebase password is built from an ID stored in a profile doc every user can read (S1).
  2. Another user can run script inside your app by putting HTML in their name and sending a friend request, a shared lesson or a link request. That script can read your AI key and student records (S2).
  3. Restoring a backup looks like it worked, but the data is gone after a reload. The import writes to an old Firestore path the app no longer reads (D1).
  4. Editing an assignment erases every student's score for it (D2). The Emergency Sub Plan printout leaves most fields blank (D3).
  5. Any event with "break" in its title cancels the whole day. "Donuts with Dads Breakfast" hides every class (L2). Tabs also reload on their own after each deploy, which can throw away an open lesson (D5).

Engineering

Foundation suggestions

E1 · Put the code under version control

Right now the only history is the dated copies in _backups/. A private Git repo gives you diffs, a way to find what broke, and one-command rollback. Commit before each deploy.

E2 · Add a small test suite

There are no tests. Start with unit tests for getWeekStart, isNoSchoolEvent, countSchoolDaysLeft and formatDate, run in the Phoenix timezone. Add one Playwright smoke test that logs into a test account and opens every view. Most bugs in this report would have been caught.

E3 · Record client errors

51 error toasts say only "Error …" and nothing is recorded anywhere. Write window.onerror and unhandledrejection events to a clientErrors collection so you see failures before teachers report them.

E4 · Preview deploys

Use firebase hosting:channel:deploy preview to test on a throwaway URL before going live. This matters more once D5 is fixed, because deploys will stop reloading open tabs.

E5 · Split and bundle app.js

Split the 880 KB single file into ES modules (auth, calendar, AI, print, students…) and bundle with esbuild. That gives you minification, dead-code warnings and files small enough to reason about. Do it gradually, one module per release.

E6 · Turn on offline persistence

Firestore's IndexedDB cache is off. Enabling it makes the app open instantly and keep working through the school's patchy Wi-Fi, with writes syncing when the connection returns.

Product

Feature suggestions

Ordered by value to a teacher who isn't you. Items tagged A1–B3 are from the August gap-closing plan and are still open.

Forgot password + email verification

Missing entirely today. Needed before any public launch, and email verification also closes the grant-spoofing hole in S3.

Autosave drafts + unsaved-change guard

Save lesson and sub-plan forms locally while typing. Ask before Esc or a backdrop click discards changes.

Trash with 30-day restore

Deleting a class, unit, event, student or resource is permanent today, protected only by a confirm(). A trash view replaces most of those prompts.

Bump lessons forward / lock to date (A3)

The snow-day feature. The shift-back logic already exists and can be generalized.

Server-side AI with a monthly allowance (B1)

Teachers get AI without finding an API key, and it removes S3 and S5 at the root. Keep bring-your-own-key as an unlimited option.

Share links without an account (A2)

Send a week's plan to an admin or co-teacher as a revocable link, with IEP, 504 and medical fields stripped.

Principal feedback inbox

Principals can leave comments, but no screen shows them to the teacher (L17). A small inbox completes the loop.

Phone-first month view

Show colored dots and a count in each day, and let a tap anywhere on the day open it. Fixes U1 and makes the app usable at the copier.

Standards library + coverage report (A1, B2)

Replace the hardcoded 225 standards and the free-text field with real codes, then show what has been taught, repeated or never covered.

Working install shortcuts

The manifest already offers "Add Lesson" and "This Week" from the home-screen icon, but the app ignores them. It's a small fix (W3).
